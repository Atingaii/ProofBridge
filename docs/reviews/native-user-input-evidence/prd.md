# 实验站原生结构化用户问答透传

最新阶段：用户用 Codex 的 `Queued follow-up inputs` 再次明确所需交互，要求先制定计划。本轮只规划，权威清单为[运行时交互补全计划](../../features/native-structured-user-input-runtime-plan.md)，待审核后实施；任务维持 in_progress。

历史基线：[二次修复及回归计划](../../features/native-structured-user-input-regression-plan.md)的六项修复已进入工作区，源码、前端、同次完整 Go 测试及构建曾通过。Codex 四种模式与 Claude Code 2.1.281 的 default／bypassPermissions 项目 helper 曾通过原生探针；这些不等同于真实模型到实际浏览器的完整验收。用户报告目标机器已更新，但新运行仍只有文字问题；当前部署版本及故障层尚未核实。详细历史见[实施记录](implement.md)。

## 目标与用户价值

实验站中的 Codex 或 Claude Code 需要用户选择、补充信息或确认关键决策时，将原生结构化问题展示到浏览器，用户选择选项或填写自定义答案后，答案回到发起提问的原生调用，保持原有会话和编排上下文。

## 已确认需求

- R1：支持 Codex 和 Claude Code 的原生结构化提问；既有 `request_user_input`／`AskUserQuestion` 适配之外，必须核实用户示例所代表的异步待答机制，具体工具名与传输契约以实际 CLI 能力为准。
- R2：优先展示工具提供的结构化选项，支持必要的自定义回答；保留问题、选项说明和原生单选/多选语义。
- R3：功能应覆盖需要执行审批和无审批信任两种模式；执行免审批不应替用户回答问题。
- R4：回答必须关联原始请求、worker、原始 turn 和 run，不得创建新的会话或编排 run 作为回传替代。阻塞调用在原 turn 恢复；异步交互按已验证原生关联机制送达，不擅自人工开启 turn 注入答案。
- R5：规划阶段先做调研和方案，实施等待用户审核；此前方案已获实施授权，本次运行时补全先提交计划，不以旧授权越过用户最新的规划要求。
- R6：遵循原生阻塞／非阻塞语义。阻塞问题等待用户，非阻塞问题允许原生执行继续；不额外暂停整个实验站，不代用户选择默认答案。
- R7：卡片区分等待回答、提交中、已送达、已关闭／失效；页面刷新恢复仍有效的问题，原生调用结束后不再接受答案。
- R8：新问题主动出现在可见问答面板，支持多请求排队、多题填写、收起后固定入口；新增问题不覆盖草稿、不反复抢焦点，逐题或整组提交遵循原生契约。
- R9：明确显示可用、未启用、不支持或未确认；运行中的能力状态以实际 run／worker 为准。无告警不再被当成能力已开启的证据。
- R10：必须用同一次真实 CLI／模型和实际浏览器证明提问、选择／自定义输入、原生送达和模型继续；普通文字、计划标记、模拟测试及独立探针不能替代。

## 已确认事实

- 本机 `codex --version` 为 0.156.1；其生成 schema 支持 `ToolRequestUserInputParams`、`ToolRequestUserInputResponse`。
- 本机 schema 含 `isBlocking`，旧 `autoResolutionMs` 标为弃用；问题支持可空 options、isOther、isSecret；响应按 question ID 映射到 answers 数组。
- 本机 `codex features list` 中 `default_mode_request_user_input` 为 under development / false。不能把接通传输等同于默认模式已可调用该工具。
- 官方 app-server 文档确认实际请求 `item/tool/requestUserInput` 及 `serverRequest/resolved` 生命周期通知；文档与本机 schema 的新旧字段存在差异，适配需要版本验证。
- 规划时本机 Claude Code 为 2.1.229，当时尚无完整 AskUserQuestion 适配；此项保留为历史基线。后续本机 2.1.281 的真实项目 helper 验证及能力门禁见[能力记录](claude-capability-verification.md)。官方文档明确 AskUserQuestion 在 bypassPermissions 下仍需交互，dontAsk 则拒绝此类调用。
- 当前审批链路存在；Codex 实验站常规 NativeSession 路径在信任模式仍用 app-server。代码锚点与候选实施顺序见 [调研记录](research.md)。

## 验收标准

- AC1：两种 CLI 在实验站发出问题后，网页正确显示全部问题和选项，并展示发起者。
- AC2：预设选项和自由回答可回传到原调用；Claude 原生多选不丢失信息；模型能够使用回答继续原上下文。
- AC3：信任模式依旧展示问题，且常规执行审批行为无回归。
- AC4：重复点击、并发 worker、切换 run 不会串答；服务端确认原生响应写出后才显示已送达，不能宣称模型已处理。
- AC5：页面刷新后能恢复仍有效的问题；CLI 已结束/请求已撤销时显示失效，不接受迟到答案。
- AC6：阻塞问题保持原调用等待；非阻塞问题不阻断事件读取、原生允许的独立工作及其完成通知。用户停止、原生撤销或进程失效时，卡片同步关闭；客户端不自动选择推荐答案。
- AC7：不支持的 CLI 版本或运行模式给出可理解的原因，不伪造原生选项。
- AC8：问题按其原生能力呈现，不依据响应数组擅自将 Codex 问题变成多选；敏感输入不进入普通日志或公开分享。

验收映射：R1→AC1/AC7；R2→AC2/AC8；R3→AC3；R4→AC2/AC4；R5→规划审核门禁；R6→AC6；R7→AC4/AC5。

## 二次审查新增验收约束

- AC9：共享出站队列短暂满载后，无需 Bridge 重连即可恢复问答投递；心跳、停止、执行审批和普通事件保持可用。
- AC10：正常问题 resolved 不终止健康原生进程；写完成事实不被稍后的关闭覆盖，实际故障仍有界清理。
- AC11：未确认提交可通过权威核对得到确定结果；允许改答前必须阻止旧提交迟到执行。排队／写入中不可编辑，多标签状态一致。
- AC12：断线期间运行结束后仍能自动恢复授权的终态回执，不重新开启执行，不能留下无限自动重试。
- AC13：问答测试不访问公网模型目录、不污染原统计测试；普通聊天、审批、连续性、终态、统计和隐私的原功能矩阵及同次全量测试通过后才可发布。

以上约束的修复及完整自动化测试已有历史记录，实际浏览器／模型验收仍缺失；具体六项问题、证据等级和门禁见二次修复计划。原 AC1–AC8 继续有效。

## 本次交互澄清新增验收约束

- AC14：覆盖用户举例的排队式异步提问。先验证真实工具／事件与生命周期；非阻塞独立工作能继续，待答请求不因不相关 turn 结束而被错误关闭，也不超出原生寿命接受答案。
- AC15：长日志和 390px 页面上新问题主动可见；单一可编辑表单支持选项、自定义输入、多个请求和题组进度。收起不取消，未提交不代答，刷新恢复有效入口。
- AC16：功能关闭、组件不兼容、CLI 未验证和可用均有明确状态；无敏感内容的阶段证据能区分未产生原生请求、传输失败和呈现失败。
- AC17：两种 CLI 在自动执行／需要审批模式下通过实际浏览器往返；至少包含产品默认新运行、原 run 继续运行和异步队列。后续模型使用仅在浏览器填写的合成测试短语，且原生关联身份匹配。

新增映射：R1/R4/R6→AC14；R8→AC15；R9→AC16；R10→AC17。完整矩阵、实施依赖及低负载约束见运行时交互补全计划。

## 首期范围

- 首期覆盖实验站内两种 CLI 的结构化用户问答及其必要的浏览器、Hub、Bridge 支持。
- 普通聊天、MCP 任意动态表单、系统通知推送、CLI 进程死亡后的原调用复活暂不扩展。
- 不改写模型普通文本中的问句为假工具调用，不让另一个 worker 代用户作答。

## 关键决策与技术门禁

- 建议复用现有连接，新增独立问答消息；不改执行审批规则，不将回答作为新 prompt。
- 首期不增加问题历史数据库；浏览器刷新靠当前有效调用恢复。Bridge/CLI 进程死亡后，旧问题失效，不承诺复活原调用。
- 规划时 Codex 默认模式功能仍在开发中、Claude MCP host 完整问答尚未实测；这些是第一阶段的原始门禁。当前仅对已验证的 CLI 精确版本和权限模式开放能力；未验证组合继续保持不可用，不以文本模拟、强制 Plan 模式或默认回答冒充完成。
- 在通过能力验证的实验站专用 Codex 进程上按需开启默认模式提问能力，不改用户全局配置。最终审核包含此兼容性选择。
