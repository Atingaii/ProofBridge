# 主线集成与实验室部署

## 目标

将已验证部署版本合并到 main，保留主线的编排设计文章与 CI；README 展示当前产品和命令行部署，
不链接 AI 部署提示词。实验室用户可选择同机 MCP、VPN + SSH 转发、或 HTTPS 直连。

## 非目标与边界

不更新任何运行中站点、Bridge、用户登录或 SQLite。不因 VPN 自动把远端地址当成本机回环。
不增加协议/数据库字段；复用 AUTOMATION_PUBLIC_URL 与 AUTOMATION_MCP_URL，并保持旧配置兼容。

## 实施

1. 三方合并 main 与部署分支；保留 main 博客路由以及部署版认证恢复、原生问答和动态界面。
2. 以 main 为源码入口，保留标准/动态构建选择；README 提供常规 CLI 部署入口与实验室地址表。
3. 完整命令部署手册覆盖首次安装、随机凭据、systemd/Caddy、VPN/SSH、HTTPS、验收、升级与回滚。
4. 个人 MCP 提示词仅在回环地址时提醒同机或 VPN + SSH 转发，不执行自动隧道或改写地址。
5. 重建嵌入资源，执行 Go、前端、关键浏览器及临时 Hub/Caddy 验证后更新 main，保留两条历史。

## 退出门禁

无合并标记；README 不含 AI 部署提示词链接；文档与代码锚点检查通过。
动态界面、主线文章、认证恢复与问答浏览器回归通过；Go 全量测试和构建通过。
内网网页/回环 MCP 临时端口验收通过；原 8088 进程与健康保持不变。

## Reviewer Q&A

- 为什么保留独立 MCP URL？网页/邮件要用实际内网地址，而 CLI 可在服务器本机或经隧道连接回环。
- VPN 是否足够？VPN 解决内网路由；个人电脑的回环仍需要本地转发，或改用受信 HTTPS 直连地址。
- 是否重写主线历史？采用有两个父提交的正常合并，既有主线与部署历史均保留。

合并后的文章图目录与 SPA 路由同名：staticHandler 必须对现有目录也返回 SPA index，
避免无尾斜杠请求被 FileServer 重定向或列目录；.svg 文件仍按真实静态资源提供。
回归覆盖两种文章路径与实际 SVG 响应，不放宽 /api 或认证统计路由。
